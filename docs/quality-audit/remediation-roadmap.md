# 整改路线

只列方案和验收。未获明确批准前，不改 `src/`。工作量是一个人熟悉这块代码时的估计，不含 live 模型回归的等待时间。

依赖关系：QA-001、QA-002、QA-005 都在命令分析器里，适合同一批改，但测试要分开写，避免一个补丁掩盖另一个。QA-003 的 `ps` 不能靠分析器修完就算完，沙箱（QA-008）目前也挡不住它。

## Phase 0：P0/P1 与数据暴露

目标：默认模式和 plan 模式恢复产品自己写明的不变量。估计 5 到 8 人日。

| 顺序 | 项 | 方案 | 验收 | 回归 |
|---|---|---|---|---|
| 1 | QA-001 | 换行拆段；拆不开就拒绝执行 | plan + `on_ask=deny` 不创建标记文件；`echo` 换行 `rm` 不是只读 | 新套件前两个用例；`tests/test_security.py` |
| 2 | QA-002 | 路径用 `samefile` 或折叠大小写后再匹配；执行前再查一次 | `.SSH/config` 与 `.ssh/config` 同一文件时 deny，内容不进工具结果 | `test_credential_case_alias_is_denied`；小写路径仍 deny |
| 3 | QA-003 | 查看父进程环境的命令改为 deny 或 ask；补剥离名单 | canary 的 key 与 `MYSQL_PWD` 都不出现在 echo 和 ps 结果里 | 新套件两条；不要打印真实环境 |
| 4 | QA-004 | Origin 比较 scheme、主机和端口 | `127.0.0.1:9999` 为 403，本页 origin 仍可建会话 | 两个 HTTP 用例加一条浏览器同源成功 |
| 5 | QA-005 | 识别 `-lc`；`find -delete` 打到 `~` 或 `/` 算灾难性；收紧 remember | bypass 下两条命令 deny；第二条不同的 `bash -lc` 会再次询问 | 参数化用例和 grant 用例 |
| 6 | QA-006 | `mock` / `flywhl-demo` 固定演示供应商；示例 11 用环境白名单 | 有假密钥时 `resolve` 仍是 mock；示例 11 在保留密钥的环境里通过且无出站 | 新用例；CI 里的示例 11 |

Phase 0 完成前不要把监听地址改成 `0.0.0.0` 做“顺手验证”。那会把 QA-004 从本机端口扩大到局域网。

## Phase 1：核心行为与默认防护

估计 3 到 5 人日。放在 Phase 0 之后，因为沙箱补不上字符串分类错误。

| 项 | 方案 | 验收 |
|---|---|---|
| QA-007 | 明确哪些 hook 失败即拒绝，默认值写进信任提示 | 超时 hook 在 fail_closed 时工具 denied |
| QA-008 | 不可信工作区不要默认 `sandbox=off`；Seatbelt 增加进程环境与网络的限制，或文档把默认档改成“无隔离”并在启动时打印 | 打开沙箱后父进程密钥读不到；工作区外写入失败 |
| QA-011 | `master.passwd` 与钥匙串查询进入硬拒绝 | bypass 下策略为 deny，测试不打开真实文件 |
| 审批后二次改写 | hook 在批准之后若再改参数，重新 evaluate，deny 则不执行 | 新增一条执行器测试 |

## Phase 2：部署与可维护性

估计 2 到 4 人日。

| 项 | 方案 | 验收 |
|---|---|---|
| QA-009 | 数据目录 0700，数据库 0600 | 新建 Store 的文件模式 |
| QA-010 | 窄视口检查器改为覆盖层，默认不与对话并排 | 390px 下对话宽度可用；桌面截图不回退 |
| 测试布局 | 把 `docs/quality-audit/tests` 收进 CI 的非 live 作业，或在 Phase 0 修完后移入 `tests/` | CI 日志里能看到这些用例 |
| 覆盖率 | 加上 pytest-cov，只做报告，不设行数门禁 | 生成报告即可，不要求百分比达标 |

## Phase 3：体验与长期债

| 项 | 方案 | 验收 |
|---|---|---|
| QA-012 | 查询串令牌只在 `/` 兑换一次 | 其他路径只带 `?token=` 时 401 |
| QA-013 | README 不再写死 240 | 与 `pytest` 收集结果一致 |
| 断电耐久 | 若要承诺断电不丢事件，再把 `synchronous` 调到 FULL，并写明吞吐代价 | 这是取舍，不是 Phase 0 的正确性 bug |
| live 套件 | 仍不进默认 CI。修完 Phase 0 后用现有 `tests/live` 做一次有密钥的抽查 | 单独记录费用和失败分类，不把随机模型失败算成 harness 缺陷 |

## 不在本次整改里的事

多租户、RBAC、独立数据库服务，是另一条产品线，不是把上面的补丁做大。当前发布形态如果仍是“本机单用户”，修完 Phase 0 就可以再评估，不需要先上 PostgreSQL。
