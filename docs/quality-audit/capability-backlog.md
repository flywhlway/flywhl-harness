# 能力扩展清单

日期：2026-10-31。

排序依据依次是：安全收益、日常使用频率、实现成本。优先级分三档：

| 级别 | 含义 |
|---|---|
| P0 | 已复现的安全缺陷，本轮必须修，明细见 [security-round2.md](security-round2.md) |
| P1 | 有明确攻击路径的防线缺口，或使用中高频缺失的能力 |
| P2 | 纵深防御，或体验上的改进 |

## 本轮已实现

| 能力 | 入口 | 说明 |
|---|---|---|
| 会话重命名、归档 | Web 侧栏、会话菜单 | 归档可以撤销，之后在侧栏「已归档」里找回 |
| 会话导出为 Markdown | Web 会话菜单或命令面板；`GET /api/sessions/{id}/export`；`flywhl export <会话> [-o 文件] [--injected]` | 导出当前分支的对话，包括工具调用和结果。加 `--injected` 会附带 harness 注入给模型的提醒 |
| 「环境与安全」页 | `#/settings`，数据来自 `GET /api/settings` | 集中显示当前实际生效的设置：模型与回退、权限与沙箱（含网络）、托管基线、hook 失败策略、MCP、访问控制、预算。桌面通知也在这里开启 |
| 审批提醒 | 标签页标题、桌面通知 | 标题里显示待审批数量；授权后发桌面通知 |
| 审批快捷键 | 键盘 `A` | 把焦点移到第一个待审批操作上。只移动焦点，批准仍要再按 Enter |
| 代码块复制与轻量高亮 | 会话时间线 | 不依赖外部库 |
| 正则搜索移出事件循环 | `grep`、`search_ref` 工具 | 搜索在子进程里执行并有超时，灾难性正则不再卡住整个服务 |
| 沙箱断网 | `sandbox_network = "deny"` | 只在 `sandbox = "macos"` 时生效；不受信任的项目配置只能收紧，不能放开 |
| 访问令牌持久化 | `~/.flywhl/server_token`，权限 0600 | 令牌默认开启；服务重启后，书签和 Cookie 照常可用 |

## 后续

| 优先级 | 能力 | 理由 |
|---|---|---|
| P1 | 命令 hook 子进程剥离密钥环境变量 | bash 和 MCP 子进程已经剥离，hook 是剩下的通道（`policy/hooks.py` 把 `os.environ` 原样传给了子进程） |
| P1 | 不再直接采信 MCP 工具注解 | 恶意服务器可以自称 `readOnlyHint`、`idempotentHint`，以此绕过审批 |
| P1 | 出口白名单 | 网络现在只能全开或全断。被注入的内容驱动外发时，最后一道防线还是空的 |
| P2 | Linux 沙箱（bubblewrap 或 Landlock） | 沙箱目前只有 macOS 原型，CI 和服务器上用不了 |
| P2 | 沙箱限制 Mach 服务 | 钥匙串查询走 Mach 服务，现在不受限制，这是 QA-008 剩下的部分 |
| P2 | 识别整条路径放在变量里的写法 | 例如 `F=/etc/passwd; cat $F`。静态分析看不到变量的值，需要在执行时检查，或依靠沙箱兜底 |
| P2 | hook 与 MCP 的准入、锁定版本；信任哈希覆盖被引用的脚本 | 供应链：现在只对配置文件做哈希，它引用的脚本内容变了也不会察觉 |
| P2 | 监控秒批和重复审批 | 现在只有审批时长等数据，出现审批疲劳时没有提示 |
| P2 | 无人值守时按规则细分自动批准 | `--yes` 会放行所有需要询问的操作，粒度太粗 |

清单里的缺口与[第 19 章总表](../governance/security.md)的“本项目状态”一列保持一致。每完成一项，两边一起更新。
