## 彩排查出并修掉的问题

| 问题 | 不修的后果 | 处理 |
|---|---|---|
| 容器里 bubblewrap 挂 `/proc` 被 Docker 的遮蔽拦下，沙箱根本没启动 | bash 一条命令也跑不了，开沙箱配置的失败看着像被沙箱拦住，其实什么都没测到 | 放开 `systempaths`，同时去掉全部 capability、禁止提权；运行器启动时探测沙箱，起不来就停 |
| 彩排只打印结果，不判定 | 上面这个问题差点被当成“区分度符合预期” | 彩排逐任务判定，不符合就退出码 1 |
| `GIT_AUTHOR_*` 撞上 `AUTH` 规则，被命令的环境变量过滤删掉 | 靠环境变量配身份时提交报身份未知 | harness 修复，有回归用例 |
| `.flywhl/` 一直显示为未跟踪 | 工作区永远不干净，`git add -A` 把会话库带进仓库 | harness 修复：目录里自动放 `.gitignore`，只列 harness 写的文件 |
| 夹具被全局 `*.log` 规则挡在版本库外 | 镜像里的题目没了输入，校验却照样通过 | `bench/tasks/.gitignore` 放行，`bench/run.sh` 用真实的忽略规则再查一遍 |
| 检查脚本没有 `TMPDIR` | `tempfile` 可能退回工作区，改变被检查的内容 | 每次检查给一个工作区外的临时目录 |

中途有两次修复走错了方向，都是提交后的自动安全审查指出来的：

- 为了不改坏 `/work/x/home/`，给脱敏规则加了后行断言，结果 JSON 里的 `\n/home/alice` 漏了过去。现在恢复严格规则，改掉试验目录的名字。
- `.flywhl/.gitignore` 第一版写的是 `*`，会把用户要提交的 `config.toml` 和 `skills/` 藏起来，而且目录已存在时不写。现在只列 harness 自己的文件，已存在的目录也写。

## 这份彩排不能说明什么

- 没有调用真实模型，通过率、费用、耗时都没有意义。沙箱开关的 0.05 秒差异只是脚本模型的数字。
- 脚本只用 bash 做这 5 道沙箱敏感题。真实模型可能换文件工具绕过去：`.git/` 里的写入走审批，无人值守时自动批准。
- 方法说明还是草案，结果绑定的版本也还没定。
