## 读数时注意

- 只统计 pytest 进程内执行的代码，测试启动的子进程不计。试过 coverage 的 `patch = ["subprocess"]`：
  第二段里，系统沙箱中的 Python 子进程写不了数据文件而报错，三个用例因此失败；总数与不测子进程时完全相同。
- `tools/regex_search.py` 的搜索在子进程里执行（防灾难性正则卡住事件循环），所以偏低。
- `tools/sandbox.py` 的 Linux 档只在 Linux 上运行，macOS 上的数字不含这部分。CI 的 coverage-audit 作业在 Ubuntu 上跑，
  没有 bubblewrap 时只隔离环境变量、不跑 macOS 专用用例，两边的数字不能直接比较。
- 只出报告，不设门禁。
