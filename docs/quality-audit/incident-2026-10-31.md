# 事故复盘：回归测试在开发机上执行了 `rm -rf ~`

- **日期：** 2026-10-31（时间均为 UTC+8）。
- **性质：** 开发过程中的事故，不是发布版本的缺陷。harness 的漏洞只是触发条件之一，这个漏洞已在第二轮修复。
- **责任：** 决定在宿主机上运行旧代码执行型测试的，是执行这轮任务的 AI Agent。
- **复盘格式：** 只追机制，不追人。

## 摘要

为了给[第二轮安全报告](security-round2.md)取“修复前”的数据，Agent 用 `git archive HEAD` 导出了旧代码，把新写的回归测试 `tests/test_hardening.py` 跑在它上面。

- **触发用例：** `test_hook_rewrite_after_approval_is_rechecked` 让 hook 把审批过的参数改写成 `rm -rf ~`，用来验证改写后的参数会被重新判定。旧代码恰好缺这道判定，命令被真实执行。
- **隔离缺口：** 测试夹具只把 `FLYWHL_HOME` 指向了临时目录，`HOME` 仍是开发者的真实家目录。
- **停止方式：** 命令运行约 120 秒，被 bash 工具的超时杀掉。

## 影响

**家目录**
- `rm` 按 APFS 目录项的哈希顺序遍历，排在 `~/OrbStack` 之前的顶层条目被删除，包括几个项目数据目录，以及多个命令行工具的配置目录（登录态、键盘映射等）。
- 现存的 100 多个顶层条目、`~/dev` 下的所有仓库都未受影响。

**容器**
- `~/OrbStack` 把运行中容器的根文件系统和数据卷暴露在家目录里，而且可写，删除顺着它进入了容器：
  - 11 个运行中容器的根文件系统被删坏；
  - 9 个数据卷被清空：关系库 3 个、Redis 2 个、对象存储 2 个、配置中心 1 个、模拟器 1 个；
  - 一个经 bind mount 挂进容器的数据目录被清空。
- 其余 256 个数据卷和全部镜像完好。

## 根因

1. **直接原因：** 旧代码对“审批后又被 hook 改写”的参数不再做权限判定，而回归测试的载荷又是真实的破坏命令。
2. **隔离缺口：** `tests/conftest.py` 只隔离了 `FLYWHL_HOME`。bash 工具继承了测试进程的环境，`~` 展开成真实的家目录。测试默认 `sandbox = "off"`，命令拥有开发者的全部文件权限。
3. **决策失误：** 安全回归测试的失败方式，就是把载荷执行一遍；旧代码对这些测试来说是“已知会失败”的。Agent 却把它当成普通测试在宿主机上运行，运行前也没有检查哪些载荷会被真正执行。
4. **放大因素：**
   - `~/OrbStack` 让家目录里的删除穿进了容器的文件系统和数据卷；
   - 超时之前，命令有整整 120 秒可以执行；
   - 开发机没有 Time Machine 备份，也没有 APFS 快照，删除无法回滚。

## 做对了什么

- 1 分钟内发现问题。先确认删除进程已经停止，再做只读评估；评估完成前没有重启任何容器。
- 抢救先从运行中的进程复制“已删除但仍被打开”的文件，再做逻辑导出。容器一旦停止，这条路就断了。
- 删除范围是推算出来的，不是猜的：
  - 用 APFS 目录哈希复现 `readdir` 的顺序：先做 NFD 规范化和 casefold，再按 UTF-32LE 编码，算 CRC32C，取低 22 位；
  - 用现存条目验证，逆序对为 0。
- 重建站点服务前先备份对象存储，再让新实例从加密共享状态拉取数据。

## 做错了什么

- 运行了不该在宿主机上运行的测试，见根因 3。
- 对一个关系库直接做了逻辑导出。读到一张已删除且没被打开的表时，数据库进程崩溃，业务数据没能拿到。应该先原样复制进程打开着的文件。
- 发现键盘映射工具的旧规则还留在进程内存里时，没有第一时间提醒“不要打开它的设置界面”。设置界面一保存新配置，内存里的旧规则就被替换了。

## 改进项

| 项 | 状态 |
|---|---|
| 会真正执行的用例改用无害哨兵载荷（`touch pwned.txt` 加 deny 规则）；只做静态判定、不执行的用例保留真实字符串 | 已完成 |
| 根目录 `conftest.py` 把 `HOME`、`FLYWHL_HOME` 指向临时目录，`tests/` 与审计套件 `docs/quality-audit/tests` 都经过它 | 已完成 |
| 测试在外层系统沙箱里跑：`scripts/safe_pytest.py` 用 Seatbelt / bubblewrap 把测试进程和所有子进程限制在一个临时目录里，读不到真实家目录；直接运行 `pytest` 也会自动转过去 | 已完成 |
| 执行绊线：子进程启动前拒绝灾难性命令和对真实家目录的破坏性操作（含 `shutil.rmtree`），并让当前测试失败。沙箱不在的场合（第二段、没有 bubblewrap 的 Linux）由它兜底 | 已完成 |
| hook 改写参数后重新判定（包括审批后的改写）；`pre_tool_use` 的命令 hook 默认失败即拒绝（fail-closed） | 已完成，见 [security-round2.md](security-round2.md) |
| 写入开发者的全局 Agent 指令：<br>• 旧代码的执行型测试不在宿主机上跑<br>• 载荷用哨兵<br>• 破坏性命令先展开目标<br>• 规定误删后的处置顺序 | 已完成 |
| 开发机上的 Agent 自身再加一道：全局 PreToolUse hook `~/.claude/hooks/catastrophic_guard.py`。Bash、Monitor、终端面板的命令执行前，拦下：<br>• 目标是家目录、根目录或空变量的 `rm -r`<br>• 格式化（`mkfs`、`newfs`、`diskutil erase*`）<br>• `dd` 写设备<br>• 删数据卷（`docker volume rm/prune`、`compose down -v`）<br>按开发者的决定，不开全局沙箱，也不限制写入范围。<br>这道 hook 只看 Agent 直接发出的命令，测试进程再起的子进程它看不到，而本次事故走的正是这条路。那条路由上面的外层沙箱和执行绊线兜住 | 已完成：对照测试 71 项通过；在三个入口用自检标记实测，命令都在执行前被拒绝 |
| 开发机开启 Time Machine；常用工具的配置纳入 dotfiles 仓库 | 建议，由开发者执行 |
