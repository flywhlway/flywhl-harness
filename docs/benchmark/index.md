# 基准

这里用数据回答三个问题：harness 的机制在真实模型下成不成立，默认开沙箱要付出多少代价，轨迹回放是不是真的确定。

**第一次结果已发布。** 方案 `2026-11`，提交 `333bbb3`，花费 1.90 美元（账本估算）。逐项数字、每个失败的归类依据和运行偏差见[结果页](./results.md)，脱敏后的原始数据在 [GitHub Release](https://github.com/flywhlway/flywhl-harness/releases/tag/benchmark-2026-11)。

| 问题 | 结果 | 读这个数字时 |
|---|---|---|
| Q1：机制在真实模型下成立吗 | 5 家模型、24 个场景、各 3 次。四家全过，MiniMax 66/69。3 个失败都归为模型随机，harness 缺陷 0 个 | 不是模型排名，场景测的是 harness |
| Q2：开沙箱的代价（普通任务） | 25 个任务：开 74/75，关 71/75，配对检验 p = 1.0。每次试验多用时间的中位数 0.35 秒，费用几乎相同 | 没测出差异，不等于没有影响 |
| Q2：开沙箱的代价（沙箱敏感任务） | 5 个任务：4 个开沙箱 0/3、关沙箱 3/3，1 个两边都 3/3。费用 0.25 和 0.06 美元 | 这 5 个是专门碰边界的，比例是我们选的，不代表日常 |
| Q3：回放确定吗 | 回放 555 条轨迹，分叉 0 条 | 只说明记录下来的运行能重放 |

有两点要一起看：

- `env-git-config` 开沙箱 3/3，靠的是文件工具改 `.git/config` 在无人值守时被自动批准。`env-git-hook` 开沙箱的 3 次里有 2 次，模型走同一条路绕开了 hook 的只读保护。这个问题已修复：文件工具写沙箱里只读的位置现在要人当场确认，无人值守时拒绝。这两个任务在修复后的提交上各重跑 3 次，开沙箱都是 0/3，关沙箱都是 3/3，已发布的 555 条轨迹回放分叉仍是 0。上表是修复前的数字，不和重跑结果混算，见[回归记录](https://github.com/flywhlway/flywhl-harness/blob/main/docs/quality-audit/evidence/bench-regress-2026-11-05.md)。0.2.0 版本包含这个修复，`src/` 比 `333bbb3` 只多这一处改动。
- 第一次运行中途崩溃，原因在基准的容器配置，不在 harness。4 次试验作废后重跑，经过写在结果页的偏差记录里。

准备过程中已经有一个发现：确定性回放漏掉了几种录制时从外部进来的输入。真实模型写的压缩摘要、人的插话、恢复说明、验收命令的结果，回放时都不是从轨迹里取的。这些问题已经修复，回归用例在 `tests/test_replay.py`。
